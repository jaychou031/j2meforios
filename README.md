# 掌上 J2ME · iPhone 13 / iOS 15.5

基于 nano_j2me 的原生 iOS 移植。当前源码为 **0.1.6（build 7）开发版**。针对后台恢复、边缘触摸延迟和音频空转增加修复，新增可选 30 FPS 省电模式。保留离线采样音源和原有游戏控制。Xcode 编译、手机触摸/恢复、听感和实际耗电仍需本次真机验收。

## 当前代码

- C99 核心，关闭 JIT，32 MiB Java 堆，默认 Nokia 6230 档案。
- UIKit 游戏列表、文件选择器导入 JAR、内置 Korvo 演示。
- 横竖屏自动布局、当前方向锁定、完整数字键盘、方向/FIRE、A/B/C/D、软键和 CLEAR。
- 多指按键引用计数、按下/松开事件、画面触控；旋转和切后台释放按键。
- 0.1.1：按键缝隙可触发，按住时边缘容错 6 pt；相同几何尺寸的重复布局不释放按键，输入唤醒 VM 等待，画面与输入分锁并按脏区域重绘。
- 0.1.2：游戏画面改由独立 UIImageView 显示，不再在每帧绘制键盘；输入与日志、音频操作分锁，快速按下/松开分输入批次交付，日志附带触摸交付和队列延迟统计。
- 0.1.3：原核心的 Thread.yield 空操作改为当前 Java 线程协作等待一个毫秒时钟单位，避免高速空转令游戏的整数平均时间增量归零。其他 Java 线程与宿主 UI 不随此调用阻塞，游戏时钟不加速。
- 列表左滑或点击 ⓘ 可删除导入的游戏及其独立存档，或只清空数据（RMS）。执行前确认；内置演示只允许清空数据。共享 `Files` 导出目录保持原样。
- 应用图标采用用户指定 BBK9588-J2ME 项目的红蓝咖啡杯资源，白色底；来源与生成方式见 `ios/IconSource/README.md`。
- 240×320、176×208、128×160、320×240；等比最大尺寸/物理像素整数倍缩放。
- 独立 VM 工作线程、帧缓冲快照、变动画面 FPS、设置持久化。
- AudioQueue PCM 输出、音调播放；MIDI 默认使用随 App 打包的 GeneralUser GS SoftSynth 1.44 音色库，加载失败回退原波形音源。MP3、AMR-NB、WAV 等沿用原核心路径。
- 使用 JAR 内容 SHA-256 作为导入游戏的存档 ID，同内容重命名不影响存档。
- 正常退出经过上游 destroyApp；切后台暂停工作线程。系统强制杀进程不能保证调用游戏退出保存。
- 日志保留在“文件 → 我的 iPhone → 掌上 J2ME → latest-session.log”，列表设置可分享日志。

## 本地文件

```text
ios/                 iOS 界面、平台适配、音频、便携布局/按键逻辑
scripts/             源码验证、构建、打包、核心冒烟测试
tests/               布局/按键 C++ 测试、IPA 打包 Python 测试
cmake/               核心兼容性构建补丁（生成副本，不改上游文件）
.github/workflows/   GitHub Actions
upstream.lock.json   上游主项目及核心的固定提交
audio-dependencies.lock.json  音源代码、音色库、许可证与下载包的 SHA-256
third_party/         TinySoundFont 头文件和许可证（需要上传）
ios/SoundFont/       随 App 打包的 SF2 音色库和许可证（需要上传）
upstream/            手动下载的原工程（不上传到新仓库）
build/               所有本地构建和测试临时文件
dist/                产物
```

本项目所有主动生成的资料与产物留在 j2meforios 内。构建脚本将可配置临时目录放在 build/tmp。上游目录保持原样；CI 从固定提交下载主工程和核心子模块，在构建目录生成 Canvas 实例查询、Thread.yield、端口统计和 MIDI 音源接入副本。用户的 `jars/`、下载文件和本地回放证据均不上传。

## 第一次 GitHub 构建

目标仓库：`jaychou031/j2meforios`。已确认远端 main 有初始化 README，不能直接在另一个独立 Git 历史上强制推送。

1. 在本目录打开你平时使用的 PowerShell，运行上传脚本。脚本在本项目的 build 子目录克隆现有仓库、复制移植文件并追加提交，保留远端历史，不使用 force push。

```powershell
Set-Location 'F:\软件\vibecoding\j2meforios'
powershell -ExecutionPolicy Bypass -File .\scripts\publish.ps1
```

`.gitignore` 已排除 upstream、下载目录、构建缓存、IPA 和 dist；不要用 `git add -f` 把整个上游复制进去。脚本使用你现有的 Git 登录和提交身份；如果缺少 user.name / user.email，会提示输入，仅保存到本次上传用的仓库配置。不会替你填写身份或修改全局 Git 配置。

2. 打开仓库 **Actions → Build iOS IPA** 查看自动构建；也可点 **Run workflow** 手动触发。
3. 全部检查成功后下载 **J2MEForIOS-unsigned-IPA** artifact，解压得到 `J2MEForIOS-unsigned.ipa`。**J2MEForIOS-build-logs** 仅包含诊断日志，不是安装包；构建失败时请提供其中的 `build-ios.log`。
4. 将 IPA 通过 TrollStore 安装。此构建不需要 Apple 开发者证书，没有申请 JIT 或私有权限。

流程固定 macos-15 / Xcode 16.4，部署目标 iOS 15.5。runner 若移除这个 Xcode 版本，需显式调整工作流，不能盲目换最新版本。构建输出检查 Mach-O 的 arm64、iOS 真机平台和最低系统，避免误打模拟器包。

如使用浏览器上传源码，可解压 `dist/j2meforios-source.zip` 后上传其中的文件和目录，务必包含隐藏的 `.github` 目录。不要把 ZIP 文件本身当作项目源码上传。

## 首轮手机验收

1. 启动内置演示：确认三条色带依次为红、绿、蓝，中文可见、黄色方块移动。
2. 按 FIRE 或 5，听是否发声；按方向、数字和软键，观察 Key 值变化。
3. 触摸画面：青色框应跟随触点；方向和数字键应能同时按住。
4. 旋转手机：游戏继续运行、画面不拉伸、按钮不被刘海/手势条遮挡；测试方向锁定。
5. 切后台再返回：声音和动画恢复、没有卡键。
6. 从菜单正常退出，再次进入演示：RMS boot 应增加；结束应用再启动再测试。
7. 导入自己的 JAR 测试实际关卡。失败时记录游戏文件名、所选分辨率、复现步骤，导出日志。

## 0.1.1 输入修复验收

1. 内置演示和原先出现卡顿的游戏各试一次，横竖屏都测试。
2. 按住方向键至少 10 秒，手指在按键边缘轻微移动，观察高亮是否无故熄灭、游戏是否意外停止移动。
3. 从 4 连续滑到 5、6：旧键应释放、新键应高亮；滑到键盘外或抬手后不应卡键。
4. 同时按住方向和 FIRE/5；松开一个手指不应影响另一个。开启 FPS 显示后重复长按。
5. 按住时旋转、打开菜单或切后台，返回后旧键应释放，新的按下应正常响应。

若仍有问题，请记录游戏名、哪个按键、按钮是否变绿、游戏画面是否也卡住及 FPS。当前修复没有更改上游 Java 按键语义或增加自动连发，不能据此断言解释器性能或游戏兼容性问题已解决。

## 0.1.2 验收与边界

- 核心按键查询：用户 City Bloxx 1.0.8 的接口调用会在原核心抛出 `AbstractMethodError: p does not implement m.getGameAction`。构建补丁保留原有静态调用入口并增加实例入口，本地已验证菜单方向选择、进入 Quick game 和返回菜单；完整玩法、楼块显示和冷启动存档仍需手机验证。
- 快速换键：在原来卡顿的游戏中交替点击方向和 FIRE/5，同时观察绿色反馈。正常退出后导出日志，其中 `UI_TOUCH` 是系统触摸交付延迟，`INPUT` 是事件入队至核心读取的延迟，`UI_MAIN` 记录显示回调最长间隔。指标只能用于定位，不能直接等同游戏动作延迟。
- 清空数据：确认后删除该游戏 `Saves/<id>` 的 RMS 数据，保留 JAR；下次启动由游戏自行重建存档。删除游戏另外移除 `Games/<file>.jar` 和标题文件。共享 `Files` 不删，其他游戏的 JAR、存档不删。不要先卸载应用来更新，否则可能影响现有数据。
- 图标：更新安装后检查主屏幕咖啡杯图标和版本 0.1.2（3）；图标目录已包含 iPhone 全部需要的尺寸以及 1024 像素图。
- Windows 本地使用 MSVC 编译的独立测试宿主进行核心回放；Windows 适配只在 `build/host` 内，用于测试，不能代替 iOS/ARM64 验证。

## 0.1.3 验收与边界

- 用户反馈上一轮按键略有改善、City Bloxx 菜单可选择，但 Build city 后仍无法继续。已复现城市网格停滞：游戏 8 次循环的毫秒增量取平均后持续为 0，教程的 600 ms 门槛到不了。协作 yield 补丁后，干净存档回放推进到教程、吊车、三层楼及 Population 4 / Tower height 3 结算，正常保存退出。测试证据在本地 `build/city-013-clean`；不代表全部关卡通过或已完成手机验证。
- 输入：减少 yield 空转可以降低解释器无用工作，尚不能证明手机快速换键完全修复。继续测试高操作频率游戏，若仍卡顿，正常结束后导出日志对照 `UI_TOUCH` / `INPUT` / `UI_MAIN`。
- PCM：首批真实样本到达后才启动；设备缓冲按约 10 ms 分块，总待播数据限制为约 120 ms（含已交给设备的帧），短尾按实际长度排队；首批声音前应用用户音量。简单提示音增加 5 ms 淡入淡出。没有修改音乐采样率或游戏音高。
- 音频日志 `AUDIO` 记录最近一次 PCM 打开后的帧数、空缓冲、满幅采样和错误；`empty_frames` 也可能包含自然结束后的空回调，不能单独判为卡顿。`AUDIO_MIDI=core_waveform_synth` 表示仍使用核心简化合成器，不是原手机音色；本次不声称已解决全部失真。
- 先更新安装 0.1.6（7），不必卸载或清空已有存档。城市模式新手提示按 5/FIRE 翻页；部分提示会等待短暂动画，不能在刚出现的一瞬间跳过。旧存档仍异常时，先导出日志再考虑游戏列表的清空数据操作。

## 0.1.5 音频升级与验收

- 固定音源文件原始字节及 SHA-256，音色库约 29.8 MiB，打包在 App 内；无需在手机端下载。首次使用在 VM 工作线程加载，采样数据缓存约 60 MiB，多个音轨/流共享采样，各自保持音符和控制器状态；此内存不属于 32 MiB Java 堆。
- 原 MIDI 解析、事件时间、TempoControl/RateControl、MIDIControl、循环和定位继续使用固定核心；仅音符合成改为采样音源。立体声 22050 Hz 与原核心采样率契约一致。保留程序/鼓组、音量/表情、声像、弯音/范围、延音踏板、CC1 调制；CC91/93 使用外部简易混响/合唱，不能等同某台旧手机的效果器或完整 SoundFont 调制器。
- 输出保留余量并加软限幅；末尾 5 ms 淡出。原核心给出的尾音长度不变，较长的音色库释放尾音可能被淡出截短。原解析器不支持的格式、事件及容量限制也没有因此全部解决。
- 日志开头应出现 `SOUNDFONT loaded`；结尾 `AUDIO_MIDI soundfont_streams` 为本次会话打开的采样流数，`waveform_fallbacks` 应为 0，`errors` 应为 0。循环和定位可能增加流数；`limited_samples` 代表软限幅处理的样本数量，不是 AudioQueue 丢帧。正常退出后 `active_streams` 应为 0。无需 MIDI 的游戏可以显示 0 个采样流。
- 本地验证：20 段用户游戏 MIDI 均有输出、无满幅削波/合成错误；City Bloxx 开启新音源的 30 秒回放到达三层楼和结算。Windows headless 不模拟 iPhone 音频设备，不能以这些结果代替听感与触摸验收。
- 手机更新后先确认日志 `APP_VERSION=0.1.5 BUILD=6`，保留原存档测试 City Bloxx 城市地图；随后比较同一段音乐、音量调整、软键退出/重新进入、后台恢复和横竖屏快速换键。若仍有破音或卡键，正常退出后导出新日志。

## 0.1.6 恢复、输入与省电验收

- 游戏暂停门控与音频可用状态分开：进入前台主动重试音频激活，即使没有收到中断结束通知也允许游戏继续。菜单暂停仍保持；游戏时钟扣除后台/菜单暂停时长，避免返回时游戏时间突然跨越。只有原本正在播放的提示音才在恢复时继续。
- 游戏界面请求延后边缘系统手势，并在显示期间禁用导航返回手势；离开游戏时恢复导航状态。日志增加距左右/底部 24 pt 区域的触摸交付统计，用于验证边缘延迟是否改善。UI_TOUCH 是 UIKit 交付前等待，不能与 INPUT 的 VM 队列延迟混为一谈。
- AudioQueue 无数据时停放空缓冲，由 VM 线程暂停空队列；新 PCM 到达再启动，取消原先反复发送静音块的回调循环。销毁前先使队列失效，销毁中的回调不再填充/入队。增加每个关闭流的 PCM_CLOSE 记录、恢复供数前的 gaps/gap_silence_frames。自然结束后不再供数不计为确认断粮；真实驱动恢复仍需手机验证。
- VM 退出后按工作线程清理游戏未关闭的采样流，避免跨游戏积累；不影响其他工作线程拥有的流。
- 暂停期间停用 CADisplayLink；游戏列表“设置”可开启省电模式，下次启动游戏时 VM 帧上限和显示刷新均为 30 FPS。系统低电量模式也启用此上限，普通模式保持 60 FPS。30 FPS 可能降低动画流畅度，未做实机功耗测量，不宣称某个省电百分比。
- “笃笃”声尚未定位为输出异常或打击乐。保留完整音乐，未用静音某件乐器来掩盖问题。本地 build/audio-diagnostics-016 提供 City Bloxx 与轩辕剑主题片段的完整/去鼓组/仅鼓组对比；不上传这些用户素材。
- 手机重点验证：确认 APP_VERSION=0.1.6 BUILD=7；后台停留后返回、开着菜单再切后台、音量与音乐恢复、横竖屏边缘快速换键。再切换省电模式重启游戏，确认 POWER frame_cap=30，对比温升、流畅度和一段固定时长的耗电；异常时从正常结束后的新日志查看 LIFECYCLE / UI_TOUCH / PCM_CLOSE。
