# 掌上 J2ME · iPhone 13 / iOS 15.5

基于 nano_j2me 的原生 iOS 移植。当前源码为 **0.1.2（build 3）开发版**，包含输入响应改进、City Bloxx 菜单键码兼容修复、游戏管理和应用图标。已做本地逻辑与核心回放测试；本版本的 Xcode 编译、UIKit 交互和手机效果待验证，不能据此声称全部游戏通过验收。

## 当前代码

- C99 核心，关闭 JIT，32 MiB Java 堆，默认 Nokia 6230 档案。
- UIKit 游戏列表、文件选择器导入 JAR、内置 Korvo 演示。
- 横竖屏自动布局、当前方向锁定、完整数字键盘、方向/FIRE、A/B/C/D、软键和 CLEAR。
- 多指按键引用计数、按下/松开事件、画面触控；旋转和切后台释放按键。
- 0.1.1：按键缝隙可触发，按住时边缘容错 6 pt；相同几何尺寸的重复布局不释放按键，输入唤醒 VM 等待，画面与输入分锁并按脏区域重绘。
- 0.1.2：游戏画面改由独立 UIImageView 显示，不再在每帧绘制键盘；输入与日志、音频操作分锁，快速按下/松开分输入批次交付，日志附带触摸交付和队列延迟统计。
- 列表左滑或点击 ⓘ 可删除导入的游戏及其独立存档，或只清空数据（RMS）。执行前确认；内置演示只允许清空数据。共享 `Files` 导出目录保持原样。
- 应用图标采用用户指定 BBK9588-J2ME 项目的红蓝咖啡杯资源，白色底；来源与生成方式见 `ios/IconSource/README.md`。
- 240×320、176×208、128×160、320×240；等比最大尺寸/物理像素整数倍缩放。
- 独立 VM 工作线程、帧缓冲快照、变动画面 FPS、设置持久化。
- AudioQueue PCM 输出、音调播放；保留核心的软件 MIDI、MP3、AMR-NB、WAV 等能力，实际音频效果待手机测试。
- 使用 JAR 内容 SHA-256 作为导入游戏的存档 ID，同内容重命名不影响存档。
- 正常退出经过上游 destroyApp；切后台暂停工作线程。系统强制杀进程不能保证调用游戏退出保存。
- 日志保留在“文件 → 我的 iPhone → 掌上 J2ME → latest-session.log”，列表设置可分享日志。

## 本地文件

```text
ios/                 iOS 界面、平台适配、音频、便携布局/按键逻辑
scripts/             源码验证、构建、打包、核心冒烟测试
tests/               布局/按键 C++ 测试、IPA 打包 Python 测试
cmake/               核心兼容性构建补丁（生成副本，不改上游文件）
.github/workflows/   GitHub Actions
upstream.lock.json   上游主项目及核心的固定提交
upstream/            手动下载的原工程（不上传到新仓库）
build/               所有本地构建和测试临时文件
dist/                产物
```

本项目所有主动生成的资料与产物留在 j2meforios 内。构建脚本将可配置临时目录放在 build/tmp。上游目录保持原样；CI 从固定提交下载主工程和核心子模块，再对构建目录中的单个源文件副本添加 Canvas 键码查询的实例兼容入口。用户的 `jars/`、下载文件和本地回放证据均不上传。

## 第一次 GitHub 构建

目标仓库：`jaychou031/j2meforios`。已确认远端 main 有初始化 README，不能直接在另一个独立 Git 历史上强制推送。

1. 在本目录打开你平时使用的 PowerShell，运行上传脚本。脚本在本项目的 build 子目录克隆现有仓库、复制移植文件并追加提交，保留远端历史，不使用 force push。

```powershell
Set-Location 'F:\软件\vibecoding\j2meforios'
powershell -ExecutionPolicy Bypass -File .\scripts\publish.ps1
```

`.gitignore` 已排除 upstream、下载目录、构建缓存、IPA 和 dist；不要用 `git add -f` 把整个上游复制进去。脚本使用你现有的 Git 登录和提交身份；如果缺少 user.name / user.email，会提示输入，仅保存到本次上传用的仓库配置。不会替你填写身份或修改全局 Git 配置。

2. 打开仓库 **Actions → Build iOS IPA** 查看自动构建；也可点 **Run workflow** 手动触发。
3. 全部检查成功后下载 **J2MEForIOS-unsigned-IPA** artifact，解压得到 `J2MEForIOS-unsigned.ipa`。**J2MEForIOS-build-logs** 仅包含诊断日志，不是安装包；构建失败时请提供其中的 `build-ios.log`。
4. 将 IPA 通过 TrollStore 安装。此构建不需要 Apple 开发者证书，没有申请 JIT 或私有权限。

流程固定 macos-15 / Xcode 16.4，部署目标 iOS 15.5。runner 若移除这个 Xcode 版本，需显式调整工作流，不能盲目换最新版本。构建输出检查 Mach-O 的 arm64、iOS 真机平台和最低系统，避免误打模拟器包。

如使用浏览器上传源码，可解压 `dist/j2meforios-source.zip` 后上传其中的文件和目录，务必包含隐藏的 `.github` 目录。不要把 ZIP 文件本身当作项目源码上传。

## 首轮手机验收

1. 启动内置演示：确认三条色带依次为红、绿、蓝，中文可见、黄色方块移动。
2. 按 FIRE 或 5，听是否发声；按方向、数字和软键，观察 Key 值变化。
3. 触摸画面：青色框应跟随触点；方向和数字键应能同时按住。
4. 旋转手机：游戏继续运行、画面不拉伸、按钮不被刘海/手势条遮挡；测试方向锁定。
5. 切后台再返回：声音和动画恢复、没有卡键。
6. 从菜单正常退出，再次进入演示：RMS boot 应增加；结束应用再启动再测试。
7. 导入自己的 JAR 测试实际关卡。失败时记录游戏文件名、所选分辨率、复现步骤，导出日志。

## 0.1.1 输入修复验收

1. 内置演示和原先出现卡顿的游戏各试一次，横竖屏都测试。
2. 按住方向键至少 10 秒，手指在按键边缘轻微移动，观察高亮是否无故熄灭、游戏是否意外停止移动。
3. 从 4 连续滑到 5、6：旧键应释放、新键应高亮；滑到键盘外或抬手后不应卡键。
4. 同时按住方向和 FIRE/5；松开一个手指不应影响另一个。开启 FPS 显示后重复长按。
5. 按住时旋转、打开菜单或切后台，返回后旧键应释放，新的按下应正常响应。

若仍有问题，请记录游戏名、哪个按键、按钮是否变绿、游戏画面是否也卡住及 FPS。当前修复没有更改上游 Java 按键语义或增加自动连发，不能据此断言解释器性能或游戏兼容性问题已解决。

## 0.1.2 验收与边界

- 核心按键查询：用户 City Bloxx 1.0.8 的接口调用会在原核心抛出 `AbstractMethodError: p does not implement m.getGameAction`。构建补丁保留原有静态调用入口并增加实例入口，本地已验证菜单方向选择、进入 Quick game 和返回菜单；完整玩法、楼块显示和冷启动存档仍需手机验证。
- 快速换键：在原来卡顿的游戏中交替点击方向和 FIRE/5，同时观察绿色反馈。正常退出后导出日志，其中 `UI_TOUCH` 是系统触摸交付延迟，`INPUT` 是事件入队至核心读取的延迟，`UI_MAIN` 记录显示回调最长间隔。指标只能用于定位，不能直接等同游戏动作延迟。
- 清空数据：确认后删除该游戏 `Saves/<id>` 的 RMS 数据，保留 JAR；下次启动由游戏自行重建存档。删除游戏另外移除 `Games/<file>.jar` 和标题文件。共享 `Files` 不删，其他游戏的 JAR、存档不删。不要先卸载应用来更新，否则可能影响现有数据。
- 图标：更新安装后检查主屏幕咖啡杯图标和版本 0.1.2（3）；图标目录已包含 iPhone 全部需要的尺寸以及 1024 像素图。
- Windows 本地使用 MSVC 编译的独立测试宿主进行核心回放；Windows 适配只在 `build/host` 内，用于测试，不能代替 iOS/ARM64 验证。
